# Index format — the frozen grammar

An `index.md` enumerates a directory's contents so a human or an agent can see what exists before
opening anything. That is **progressive disclosure**, and it is the entire reason a corpus is worth
formatting: one read answers "which document covers X", "does one for Y exist", and "what is this
folder", without a grep and without a guess.

Generate these with `${CLAUDE_PLUGIN_ROOT}/skills/okf-maintain/scripts/okf.mjs index`. This document exists so you can review the output and
recognise a hand-edit, not so you can render one by hand.

## Which dialect — the manifest decides, never a flag

There are two row shapes, and the repository's manifest chooses between them. `docs/okf.yaml` (or
`okf.yaml`) whose `required_keys` names **both `id` and `status`** selects the **profiled** dialect;
every other repository — no manifest at all, or one requiring neither key — gets the **default**
one. Those two keys are exactly what the profiled row projects, so a repository already demanding
them of every concept document has said its catalog is an id-and-status catalog.

The selector is the manifest rather than a command-line flag on purpose. A flag is supplied per
invocation, so the first run that forgets it renders half a chain in the other grammar — and
nothing fails, because each file is individually well-formed and only the chain is incoherent. Read
from the manifest, the dialect is a property of the bundle, the same for every directory in it.

## The grammar

The default dialect groups by `type` and gives subdirectories their own section:

```markdown
<!-- generated by okf.mjs - do not edit; regenerate after changing frontmatter -->

# Playbook

* [Incident response: data freshness alert](incident-response.md) - Steps to triage a freshness alert on the orders pipeline.
* [Rotating the signing key](key-rotation.md) - Quarterly rotation procedure for the release signing key.

# Reference

* [Event schema](event-schema.md) - Field-by-field description of the analytics event payload.

# Subdirectories

* [requirements](requirements/index.md) - Functional and non-functional requirements.
```

The profiled dialect groups by nothing — one heading, one list, an id and a status on every row:

```markdown
# requirements

<!-- generated by okf.mjs - do not edit; regenerate after changing concept frontmatter -->

* [FR-001 — Ingest the nightly partner feed](FR-001-partner-feed.md) - **Approved** — Accepts the nightly drop and rejects duplicate orders.
* [FR-002 — Replay a failed partner drop](FR-002-replay.md) - **Draft** — Operator-triggered replay of one night's file.
* [acceptance](acceptance/index.md)
```

Rules, all mechanical. Where a rule differs by dialect it says both halves; the rest hold in each.

1. **No frontmatter** on an index, with exactly one exception: the bundle-root `index.md` carries
   `okf_version: "0.2"` (§12), in **both** dialects. A profile selects a row shape, never a format
   version — v0.2 is the only version there is. No other index carries frontmatter at all.
2. **The generation marker** is what tells the tool a file is its own to rewrite, so every index
   carries one and its bytes differ per dialect. Default: it is the first content line. Profiled: it
   follows the heading, one blank line down. Full list below.
3. **Headings.** Default: one `# <Type>` per distinct `type` among the directory's own documents,
   sorted alphabetically, with `# Other` for documents carrying no `type`. Profiled: exactly one
   heading, the **directory's own basename**, and every row lives under it.
4. Entries are sorted by title, case-insensitively. In the profiled dialect the sort key is the
   whole composite `<id> — <title>`, so a folder of `FR-` documents reads in id order rather than in
   title order.
5. **Entry form.** Default: `* [<title>](<link>) - <description>`. Profiled:
   `* [<id> — <title>](<link>) - **<status>** — <description>` — the link is still followed by
   ` - `, and the two **em dashes** are what separate the id from the title and the status from the
   description. In both, the title degrades: frontmatter `title`, then the first `# ` heading in the
   body (ignoring fenced blocks, where a `#` is a shell comment), then the filename stem. When
   `description` is absent the entry ends at the link with **no trailing separator** — an empty
   description is a visible gap, not a dangling dash.
6. A profiled document missing `id` or `status` renders in the **default** row shape rather than
   bolding an empty string, and is named on stderr as `unprofiled-document: <path>`. A half-written
   row reads as a catalog entry and answers none of the questions a catalog is asked.
7. A `description` is collapsed to one line, and one longer than **512 characters is dropped**,
   rendering the same bare `* [<title>](<link>)` as an absent one. The script never truncates: a
   machine-cut half-sentence is a summary no author wrote, sitting in the field consumers trust
   most. A dropped one is named on stderr so the frontmatter gets shortened rather than silently
   losing its entry — `long-description: docs/requirements/FR-001.md (712 chars, max 512)`.
8. **Subdirectories** link `<dir>/index.md` in both. Default: collected under a single
   `# Subdirectories` heading, sorted, each carrying the one-line description you supplied.
   Profiled: inline in the same list, after the documents, ordered by the manifest's
   `concept_folders` and then alphabetically — and with **no description slot**, which is why
   `needs-description:` never fires in a profiled bundle and why there is no round-trip store to
   keep there.
9. Sections separated by one blank line; the file ends with exactly one trailing newline.
10. `index.md` and `log.md` are reserved (§3.1) and never appear as entries.
11. **Every other markdown file appears**, readme and contributing guide included. A document is
    listed because it exists, not because its folder or kind was registered somewhere. Rule 5 is
    what makes this free: the row degrades all the way to a filename, so listing never obliges a
    file to carry frontmatter. Which documents must carry required keys is a separate question, and
    `check` still answers it the same way.

The separator between a link and what follows it is ` - ` (space hyphen space). It is a small thing
that varies every time a human writes one, which is why a script writes them.

## The generation markers

Three strings, and the bytes are the format — an em dash and a hyphen are indistinguishable at a
glance, so compare them with a script rather than by eye.

| Marker | Written | Means |
|---|---|---|
| `<!-- generated by okf.mjs - do not edit; regenerate after changing frontmatter -->` | Default dialect | This file is okf.mjs's to rewrite |
| `<!-- generated by okf.mjs - do not edit; regenerate after changing concept frontmatter -->` | Profiled dialect | The same, in the richer grammar |
| `<!-- generated by okf-index-gen.mjs — do not edit; regenerate after changing concept frontmatter -->` | Never | A retired generator's catalog, eligible for adoption |

The two written markers differ so that a generator predating the profiled renderer does not
recognise the profiled one, and refuses the file instead of flattening an id-and-status catalog
into rows that carry neither. The third is recognised only so such a catalog can be **adopted** —
see `adoption.md`. It is never emitted: stamping forward the name of a binary that is on no disk
anywhere is the defect that recognition exists to end, not a format worth continuing.

An index carrying none of the three was written by another hand or another tool. It is left
byte-identical and reported as `foreign-index:`.

## Chained roots

Every directory containing markdown gets an index — except those `.okfignore` declares unowned, and
a Claude Code plugin's `commands/`, `agents/` and `skills/` payload, which the loader owns — and
the walk is **deepest-first** so a subdirectory's description exists by the time its parent is
written:

```
repo/
  index.md              <- entry point; links docs/ and any root-level concepts
  docs/
    index.md            <- links each concept folder
    requirements/
      index.md          <- links the requirement documents
    adr/
      index.md
```

This is not a special case bolted on for repositories. It is the general recursion: index every
directory that holds markdown, and the chain falls out. A repo whose documentation lives only in
`docs/` gets two roots; one with markdown at top level gets a root index that carries both its own
concepts and a `# Subdirectories` section.

`./index.md` is the address you give agents (see `adoption.md`). Keeping it generated rather than
hand-written is what makes it safe to point everything at.

## What the script does, and what you must do

The split is not arbitrary — it follows what can be derived from the corpus and what cannot.

| Derived — the script | Judged — you |
|---|---|
| Walking directories, deepest-first | Writing a subdirectory's one-line description |
| Choosing the dialect from `required_keys` | Deciding whether this repository is an id-and-status one |
| Reading `id` / `status` / `type` / `title` / `description` | Fixing an inconsistent `type` across documents |
| Grouping, sorting, rendering, trailing newline | Deciding a document's `description` when it has none |
| Preserving a subdirectory description already in the index | Confirming a description still matches the folder |
| Folding a `>` or `|` block scalar into its text | Shortening a `description` the index refused to carry |
| Skipping what `.okfignore` names, and reporting it | Deciding which paths another tool owns |

Every row on the right is a judgement the corpus does not state. Ownership is the sharpest of them:
nothing in a markdown file says whether a generator rewrites it, so the walk cannot infer it and
will happily demand frontmatter of a file that is about to be overwritten.

The two subdirectory-description rows belong to the **default** dialect alone. The profiled row has
no slot for one, so nothing is asked for and nothing is preserved — one judgement fewer, at the
price of a catalog whose folders are bare links.

A **directory** has no frontmatter, so nothing in the corpus states what it is for. Upstream's own
reference implementation calls a language model to synthesize that line. Here you are that step.

The script reports the gap and continues:

```
needs-description: docs/requirements
```

Read enough of the directory to write one honest line, then supply it:

```bash
node ${CLAUDE_PLUGIN_ROOT}/skills/okf-maintain/scripts/okf.mjs index . --describe docs/requirements="Functional and non-functional requirements."
```

Two shortcuts avoid asking you unnecessarily:

- **Round-trip.** On the next run the script parses the description back out of the index it wrote
  and reuses it. You supply each one once. This is why indexes have no sidecar file: the generated
  index *is* the store, and §8 forbids frontmatter that could hold it instead.
- **Single-child inheritance.** A directory holding exactly one document that has a description
  inherits it, since restating it would add nothing.

If you delete an `index.md`, its subdirectory descriptions go with it and will be asked for again.
That is the cost of having no sidecar, and it is cheap.

Both shortcuts, and the gap report that makes them necessary, are the default dialect's. A profiled
bundle never reaches this step.

## Reading an index — the discipline it buys

| Question | Answered from the index alone |
|---|---|
| Which document covers X | Scan descriptions, follow the link |
| Does a document for Y exist | Its presence or absence *is* the answer |
| What kinds of document are here | The `# <Type>` headings, in the default dialect |
| What is FR-001, and is it still a draft | The id prefix and the bolded status, in the profiled one |

Open a document only once the index has named it. The index routes; the document is the
destination reached through it.

The last two rows are the dialects' trade stated plainly: the default one answers what kinds of
document a folder holds and the profiled one answers what state each document is in. Neither
answers both, which is why the manifest picks the question the repository actually asks.

**The one legitimate grep**: a literal phrase or token inside a body — something the index
structurally cannot carry. An identity, existence, or description lookup is not that case. Being
honest about this exception is what keeps people using the index for everything else.

## Completeness is not staleness

Regenerating fixes a **stale** index. It cannot fix an **incomplete** one, and the difference is
worth holding onto: staleness is a row that disagrees with its document, incompleteness is a
document with no row anywhere. Regenerate-and-diff catches the first and is blind to the second,
because both copies come from the same walk — the document the walk never reached is missing from
each of them, and they match.

```bash
node ${CLAUDE_PLUGIN_ROOT}/skills/okf-maintain/scripts/okf.mjs coverage .
```

That runs `git ls-files --cached --others --exclude-standard` from the repository root and names
every markdown file no index links to. The enumerator has to come from outside the tool for the
comparison to mean anything, and `git` is the one at hand that is complete, honours ignore rules,
and costs nothing.

`--others` is not optional garnish. Without it the enumeration is the git *index*, which does not
yet contain the document you are adding — so the check would go green on precisely the commit that
introduces an unindexed document, and the omission would surface one commit later as a mystery.

The two enumerators disagree in one place, deliberately: the walk does not descend into
dot-directories (that way lie `.git`, `.venv` and every editor cache), while `git` happily lists a
tracked document inside one. Coverage reports it and says what to do — move it out if it is
documentation, name it in `.okfignore` if it is machine output. **Never** answer by hand-writing the
missing `index.md`. It sits outside the walk, so no regeneration touches it, and a hand-maintained
index that nothing refreshes is the failure this whole chapter is about.

## Staleness

A stale-looking index is a regeneration task, never a reason to bypass it and grep the folder. It
is a projection of frontmatter: regenerate, then re-read.

```bash
node ${CLAUDE_PLUGIN_ROOT}/skills/okf-maintain/scripts/okf.mjs index . --stdout   # render without writing, to diff against the committed file
```

Commit a regenerated index **in the same commit as the content change that caused it**. Split into
a follow-up commit, it becomes the thing someone forgets, and a corpus with a stale index is worse
than one with no index — it answers confidently and wrongly.
